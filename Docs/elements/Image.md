# Image (asset catalogs), aspectRatio, named Color

Apple docs: [Image](https://developer.apple.com/documentation/swiftui/image),
[Image.init(_:bundle:)](https://developer.apple.com/documentation/swiftui/image/init(_:bundle:)),
[resizable(capInsets:resizingMode:)](https://developer.apple.com/documentation/swiftui/image/resizable(capinsets:resizingmode:)),
[renderingMode(_:)](https://developer.apple.com/documentation/swiftui/image/renderingmode(_:)),
[interpolation(_:)](https://developer.apple.com/documentation/swiftui/image/interpolation(_:)),
[aspectRatio(_:contentMode:)](https://developer.apple.com/documentation/swiftui/view/aspectratio(_:contentmode:)-771ow),
[scaledToFit](https://developer.apple.com/documentation/swiftui/view/scaledtofit()),
[Color.init(_:bundle:)](https://developer.apple.com/documentation/swiftui/color/init(_:bundle:)),
[Asset catalog format](https://developer.apple.com/library/archive/documentation/Xcode/Reference/xcode_ref-Asset_Catalog_Format/).

Images come from Xcode asset catalogs read at build time (decision 0011): `scripts/assets.py`
turns every `*.xcassets` into a manifest plus the image files, the runtime selects a variant and
the painter loads it. Fixtures draw from `Fixtures/Assets.xcassets` (generated by
`scripts/gen-fixture-assets.py`).

## API surface

| API | Notes |
|---|---|
| `Image(_ name: String, bundle: Bundle? = nil)`, `Image(decorative:bundle:)`, `Image(_:bundle:label:)` | implemented; the bundle is ignored (the manifest is the search path) and absent on wasm |
| `Image(systemName:)`, `Image(_:variableValue:bundle:)`, `Image(systemName:variableValue:)` | stub: 0 × 0, draws nothing (SF Symbols need the icon table, a later step) |
| `Image(nsImage:)`, `Image(_ cgImage:scale:orientation:label:)`, `Image(decorative:scale:orientation:)`, `Image(size:label:opaque:colorMode:renderer:)` | missing (no `CGImage`/`NSImage` on wasm) |
| `resizable(capInsets:resizingMode:)`, `Image.ResizingMode` (`stretch`, `tile`) | implemented: stretch, nine-part stretch, tile, nine-part tile |
| `renderingMode(_:)`, `Image.TemplateRenderingMode` (`template`, `original`) | implemented; `nil` restores the catalog's intent; the last call wins |
| `interpolation(_:)`, `Image.Interpolation`; `antialiased(_:)` | implemented as a smoothing on/off flag (`none` vs the rest); `antialiased` stored, no effect |
| `Image.Scale`, `View.imageScale(_:)`, `EnvironmentValues.imageScale` | stub (symbols only) |
| `View.aspectRatio(_ ratio: CGFloat?, contentMode:)`, `aspectRatio(_ size: CGSize, contentMode:)`, `scaledToFit()`, `scaledToFill()`, `ContentMode` | implemented |
| `Color(_ name: String, bundle: Bundle? = nil)` | implemented from colour sets (sRGB and extended sRGB; Display P3 components are used as sRGB and flagged approximate) |
| `ColorScheme`, `EnvironmentValues.colorScheme` | added (default `.light`); selects dark image and colour variants, nothing else reads it yet |

## Catalog rules (from Apple's format reference; consistent on both sides, not verified against actool)

- Name = folder namespaces (`provides-namespace: true`) joined with `/` plus the set name; a
  folder without the property is transparent. `Image("nested")` does not find `Folder/nested`.
- Variant selection: idiom `mac` before `universal` (others ignored); appearance matching the
  environment's `colorScheme` (`light`/`dark`) before `any`; the display scale's variant, else
  the largest scale (drawn scaled). Point size = pixel size ÷ scale.
- `template-rendering-intent: template` makes the image a template; `original` and absent do not.
- Missing name: 0 × 0, nothing drawn, no spacing lost (a `Text` after it still sits 8 pt away).

## Measured layout rules (macOS 26.2, `image/*` fixtures, 2026-09-02)

| Rule | Fixture / probe |
|---|---|
| A named image is rigid at its point size whatever the proposal: 64 × 40 from a 128 × 80 @2x file, 20 × 64 from a 2×-only set, 80 × 60 from a JPEG | `image/intrinsic` |
| A rigid image in a smaller `frame` keeps its size, centred, overflowing; `clipped()` cuts it | `image/resizable` `overflow`, `overflowClipped` |
| `resizable()` takes the proposal in both dimensions (30 × 30, 96 × 30, 300 wide for `frame(height:)`); two resizable images in an `HStack` share the width equally (150 each); unspecified dimensions fall back to the point size | `image/resizable` |
| Stack spacing is the plain-view 8 pt on every side, image to image, image to text and image to a `Color` box; vertically a `Text` keeps its font-derived distances (4.74 above, 8.15 below the 13 pt default font) | `image/stack-spacing` |
| Both text baselines of an image are its bottom edge | `image/stack-spacing` `baseline`, `lastBaseline` |
| `aspectRatio(nil, .fit)` on a resizable image proposed *w* × *h*: the largest rect of the image's ratio inside (64 × 40 in 100 × 40; 40 × 25 in 40 × 100), centred by the enclosing frame; `.fill`: the smallest covering rect (96 × 60 in 40 × 60), overflowing unless clipped | `image/aspect-ratio` |
| Explicit ratios: `aspectRatio(1, .fit)` in 60 × 40 → 40 × 40; `aspectRatio(CGSize(1, 3), .fill)` in 30 × 30 → 30 × 90 | `square`, `third` |
| One proposed dimension: `frame(width: 100)` → 100 × 62.5, `frame(height: 30)` → 48 × 30 | `widthOnly`, `heightOnly` |
| No frame: the stack's proposal is fitted (a 20 × 64 image in the 100 pt-tall row → 31.25 × 100) | `flexibleImage` |
| `aspectRatio` on a rigid image changes nothing (64 × 40 in 100 × 40); on `Color` it sizes the colour (100 × 50 in 100 × 100) | `rigid`, `colorRatio` |
| Model: ratio = explicit or the child's ideal size (`sizeThatFits(.unspecified)`); the child is proposed the fitted/filled rect and the modifier takes the child's answer | `_AspectRatioLayout` |

## Measured painting rules

| Rule | Fixture / probe |
|---|---|
| Template images are filled with the foreground colour where the source has alpha: primary (black at 85 %) by default, `foregroundColor(.red)` → 255, 56, 60, `foregroundStyle(.blue)` → 0, 136, 255 | `image/template` |
| `renderingMode(.template)` on a plain image tints it (a 64 × 40 green rectangle under `.green`, primary otherwise); `renderingMode(.original)` on a template set draws its pixels | `forced`, `forcedDefault`, `original` |
| `opacity` multiplies the drawn alpha (0.5 → 128) | `faded` |
| `resizable(capInsets:)` stretches the nine parts (corners rigid, edges stretched one way, centre both); `.tile` tiles from the top-left, the last column and row cut at the frame | `image/tiling` `sliced`, `tiled` |
| Cap insets with `.tile` tile the edges and the centre; the golden shows the bottom edge and corners missing (an AppKit drawing quirk, not reproduced: SwiftUIWeb draws all nine parts, within Tier B tolerance) | `slicedTiled` |
| A 2× file drawn at 1.5× (96 × 60 from 64 × 40) is resampled; `interpolation(.none)` picks nearest neighbour | `nearest` |

## Verification (2026-09-02)

Tier A: all 8 fixtures exact (`image/swap` steps included). Tier B: frames exact in Chromium,
WebKit and Firefox; pixels 0 % for pixel-aligned draws, ≤ 0.5 % where an image is resampled
(`image/resizable`), 1.6 % for `image/tiling` (the AppKit bottom-row quirk above). Build:
`scripts/build-wasm.sh` runs `scripts/assets.py` on the package (the fixture catalog for the
Gallery) and `index.html` includes `assets/manifest.js` before the module script; SwiftPM itself
ignores an undeclared `.xcassets` and copies a declared one verbatim, so either is fine.
