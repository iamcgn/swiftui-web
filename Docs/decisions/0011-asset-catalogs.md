# 0011. Asset catalogs are read from source, and goldens get them through `CGImage`

Date: 2026-09-02
Status: accepted

## Context

Most views worth rendering in the browser take their images and colours from an Xcode asset
catalog (`Assets.xcassets`): `Image("Logo")`, `Color("Accent")`. A catalog is a plain folder of
`Contents.json` files and image files; Xcode's `actool` compiles it into `Assets.car`, which is
what SwiftUI's named-image lookup reads at run time. Neither `actool` nor `.car` exists in a
browser, and this Mac has no Xcode either (Command Line Tools only), so the golden harness cannot
compile one.

## Evidence (macOS 26.2, SwiftUI 7.2.5, hosted window, 2026-09-02)

Whether SwiftUI's `Image(_ name:bundle:)` resolves anything but a compiled catalog:

| Image made available as | AppKit finds it | `Image("two")` frame |
|---|---|---|
| `NSImage.setName("two")` | `NSImage(named:)` yes | 0 × 0 |
| `two@2x.png` next to the executable (`Bundle.main`) | `Bundle.main.image(forResource:)` yes | 0 × 0 |
| `two@2x.png` in a `Bundle(path:)` directory, passed as `bundle:` | `image(forResource:)` yes | 0 × 0 |
| `Probe.app/Contents/Resources/two@2x.png`, run as an app bundle | yes | 0 × 0 |
| `Image(nsImage:)` / `Image(decorative:scale:)` | n/a | 64 × 40, pixels drawn |

So a named image only ever resolves from a `.car`. Of the two direct initialisers, `NSImage`
ignores `.renderingMode(.template)` (a non-template `NSImage` stayed green under a blue foreground)
while `CGImage` honours it, and honours `.renderingMode(.original)` after it. A `CGImage` without
an alpha channel (a decoded JPEG, `noneSkipLast`) draws nothing; redrawn into a premultiplied
sRGB bitmap it draws.

SwiftPM (6.3.3) neither compiles nor complains about an `.xcassets` directory: undeclared, it is
ignored silently for wasm and native builds; declared with `.process`, it is copied verbatim into
the resource bundle.

## Decision

- **One reader, at build time.** `scripts/assets.py` walks every `*.xcassets` under a package
  (or one catalog) the way `actool` reads it: image sets with their variants (file, scale, idiom,
  luminosity appearance, pixel size read from the PNG/JPEG/GIF header), `template-rendering-intent`,
  colour sets with their components in the three spellings Xcode writes (`"0.533"`, `"0x88"`,
  `"136"`), folder namespaces (`provides-namespace`). It writes a manifest (JSON, or a script that
  sets `window.__swiftuiwebAssets`) and copies the referenced files. The web bundle needs no `.car`,
  no `Bundle`, and no change to app sources; `scripts/build-wasm.sh` runs it.
- **Selection is the runtime's**, from the manifest: idiom `mac` before `universal` (the macOS
  platform profile), the variant matching the environment's colour scheme before an `any` one,
  the exact display scale or else the largest available; the point size is pixels ÷ scale. A
  missing name lays out at 0 × 0 and draws nothing, as measured.
- **Goldens read the same catalog.** The harness `FixtureKit` shadows `Image(_:)` and `Color(_:)`
  (an overload without the defaulted `bundle:` wins) and resolves the name from
  `Fixtures/Assets.xcassets` with the same rules at 2×, handing SwiftUI a `CGImage` via
  `Image(decorative:scale:)` plus `.renderingMode(.template)` for template sets, or a
  `Color(.sRGB, …)`. Fixture sources stay `Image("swatch")`, as an app would write them.
- The fixture catalog is generated by `scripts/gen-fixture-assets.py` (deterministic, asymmetric
  images) in the exact on-disk format Xcode writes, so the reader is exercised on real
  `Contents.json` shapes; `Fixtures/Assets.manifest.json` is its committed reader output, used by
  the headless tests.

## Consequences

- Layout and painting of catalog images are golden-backed; the *lookup rules* (namespaces, idiom,
  appearance, scale) are implemented from Apple's asset catalog format reference on both sides,
  so they are consistent but not independently verified against `actool`.
- Not supported yet, each reported by the reader: PDF and SVG image sets (Xcode rasterises them),
  symbol sets, sprite atlases, slicing metadata in `Contents.json`, high-contrast and Display P3
  variants (recorded, ignored), data sets. A dark appearance is selected when the environment's
  `colorScheme` is `.dark` but has no golden (the harness renders light only).
- `Image(_:bundle:)` accepts a `Bundle` natively; on wasm only the name is available.
